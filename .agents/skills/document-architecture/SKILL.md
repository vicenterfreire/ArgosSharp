# ArgosSharp Architecture Documentation

1. Inspect the implemented behavior and relevant tests.
2. Identify changes to architecture, dependencies, configuration,
   execution flows, persistence, messaging, and operational behavior.
3. Update existing documentation before creating new documents.
4. Create an ADR for significant accepted architectural decisions.
5. Include alternatives and trade-offs in ADRs.
6. Verify examples and commands where possible.
7. Distinguish actual behavior from future plans.

Do not modify production code.
